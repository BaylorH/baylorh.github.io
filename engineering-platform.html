The context

A problem worth solving.

AI-assisted work can lose context across sessions and scatter decisions across repositories, conversations and tools. Planning and delivery need a shared structure that humans can inspect.

My contribution

What I brought to the work.

Built an internal product suite around three responsibilities: managing the work, retaining engineering knowledge and supervising agent assignments. These tools run my own development process and the client pages I share; deeper integration remains in development.

The product

What it makes possible.

Four parts follow: The Record, Brain, Jarvis OS and the earlier experiments. The screens are local runs of each product’s own code with invented projects and people; two are existing captures, marked as such.

01

The Record · manage the work

Project management for developers, clients and connected coding agents. Agents update pages through revision-checked commands with exact-retry receipts, over connections that expire after seven days and can be revoked.

02

Brain · preserve the context

Durable engineering memory for project state, findings, repository maps, workflows and handoffs, navigable as a graph of more than a thousand linked pages.

03

Jarvis OS · coordinate execution

A supervisor that has handed bounded tasks to visible Claude Code and Codex workers in recorded trials and reports each one’s real final state. Silence is never treated as success, and an offline worker makes the whole loop testable without paid runs.

04

Where it came from

Three earlier experiments, a repository that acted as an assistant, a planner and executor split, and a session cockpit, decided which ideas were kept.

05

The working cycle

Plan a bounded milestone, pursue that work, capture questions and evidence, then review the outcome before planning the next scope. Engineering judgment and release accountability stay with the developer.

The Record · manage the work

One page per project that people and agents both keep current.

The Record holds what a project is, what is built, what is checked and what is needed next, on a page a client can read. Its owner edits it, a reader answers questions where they arise, and an approved AI agent updates it through commands that cannot be applied twice.

Brain · preserve the context

Engineering memory that the next session can find.

Brain keeps project state, findings, repository maps, workflows and handoff notes as linked pages, with a search tool every session starts from and a viewer for reading them as a graph.

Jarvis OS · coordinate execution

A supervisor that reports each worker’s real final state.

Prototype · bounded trials, the full conversational cycle is still proposed

Jarvis OS writes a goal down as steps with a test for each, hands one step to a worker inside a fence, and says plainly when a step is blocked. An offline test worker makes the whole loop checkable without a paid run; real workers were used in recorded trials.

Earlier experiments

The ideas that were kept.

A repository that acted as an assistant came first: hooks that loaded saved state at the start of a session and held work at a planning gate. Its memory and enforcement ideas fed Brain; its delegation ideas became Jarvis OS.

Engineering choices

The decisions behind the interface.

01

Give each product a clear responsibility.

The Record holds project scope and evidence, Brain retains engineering context, and Jarvis OS explores supervised agent execution. Keeping those responsibilities explicit makes unfinished integration visible.

02

Refuse to guess.

Unknown is a first-class outcome: a worker that cannot prove it finished is reported as unknown, and a retried update has exactly one effect.

The Record and Brain support my development workflow and client pages. Deeper integration with Jarvis OS is the next step.

Where it stands

In daily use, with more to connect.

Bring project context and engineering memory into a more unified assistant experience. The complete proposed integration is not presented as a finished autonomous platform.
